# Patch Management

## Scope
Track operating systems, applications, network appliances, servers, security tools, and other supported platforms that require updates.

## Patch Register

| Asset / Group | Platform | Current Version | Target Version | Criticality | Patch Window | Owner | Validation | Status |
|---|---|---|---|---|---|---|---|---|
| User Laptops | Windows | | | High | Monthly | IT | Pilot group | Planned |

## Process
1. Identify available updates.
2. Assess security and business impact.
3. Prioritize critical/high-risk patches.
4. Test on representative devices where practical.
5. Schedule deployment.
6. Communicate expected impact.
7. Deploy.
8. Validate service/device health.
9. Record failures and exceptions.
10. Report compliance.

## Exception Register
Every delayed critical patch should record reason, risk, owner, compensating control, and target remediation date.

## KPI
Patch Compliance % = compliant in-scope assets / total in-scope assets × 100.
